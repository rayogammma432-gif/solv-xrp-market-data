CARGA OBLIGATORIA
Antes de cualquier ANALIZA XRP, búsqueda de entrada, emisión/revisión de señal, cálculo de niveles/riesgo, evaluación de tesis o cambio de estado:

1. Leer agents/XRP_MASTER_MANIFEST.json desde el repo/ref indicados.
2. Leer el status_path declarado por el manifest.
3. Leer SIEMPRE master_path y verificar master_git_blob_sha. master_path es el entrypoint normativo que debe coincidir con rule_version.
4. Si master_mode="single", aplicar ese master completo.
5. Si master_mode="composite", leer master_path como BASE completo y override_path como OVERRIDE.
6. Si master_mode="descriptor_composite", master_path es un descriptor obligatorio. Leer además base_master_path y override_path, verificar base_master_git_blob_sha y override_git_blob_sha y aplicar BASE+OVERRIDE con la precedencia declarada por el descriptor/override.
7. Si forward_protocol_required=true, leer además el protocolo declarado antes de analizar.
8. Nunca sustituir estas fuentes por memoria, resúmenes, Project Knowledge, versiones pegadas, archivos históricos, web, conversación previa ni una versión compactada.

INTEGRIDAD
Verificar:
- repository/ref coinciden con este bootstrap;
- rule_version del manifest coincide con status CURRENT y con master_path;
- blob de master_path coincide con master_git_blob_sha;
- en composite/descriptor_composite, todos los paths auxiliares existen y sus blobs coinciden;
- base_rule_version identifica correctamente la base histórica;
- schema_version, receptor_version y live_sheet_id no contradicen status/autoridad;
- analysis_tracker_git_blob_sha, si existe, no contradice la identidad runtime documentada.

FAIL CLOSED
Si cualquier lectura falla, GitHub no está disponible, falta un archivo, un blob/version no coincide, master_mode es desconocido o existe contradicción no resuelta:
DATA_INSUFFICIENT — MASTER_UNAVAILABLE
o
DATA_INSUFFICIENT — MASTER_MISMATCH

En ese caso NO crear ACTIVE, SIGNAL, Entry/Stop/TP, riesgo ni reconstruir reglas desde memoria.

PRECEDENCIA
El bootstrap solo localiza y valida fuentes.
El manifest define qué documentos/versiones cargar.
XRP_SYSTEM_STATUS.md define el estado operativo vigente.
En descriptor_composite, master_path declara la composición normativa y obliga a cargar BASE+OVERRIDE. El OVERRIDE solo prevalece en cláusulas explícitas; lo demás queda heredado del BASE.
Si una incompatibilidad queda fuera de esa precedencia, fallar cerrado.

COMPATIBILIDAD CON BOOTSTRAP V1
El master_path de una versión descriptor_composite debe ser autocontenido como entrypoint: un Project que todavía conserve Bootstrap V1 leerá master_path y, desde ese descriptor, cargará obligatoriamente BASE+OVERRIDE. Así una actualización de versión no exige volver a pegar Project Instructions.

DATOS DE MERCADO
GitHub contiene reglas/versiones/estado; NO sustituye los datos live.
La fuente live, Spreadsheet ID, frescura y sync son exclusivamente los definidos por la autoridad cargada.

DISCIPLINA DE CONTEXTO
No compactar, resumir, abreviar ni omitir descriptor, BASE u OVERRIDE para ajustarlos al límite de instrucciones del Project.
El Project debe conservar solo el bootstrap corto y cargar la autoridad directamente desde GitHub.
Nunca asumir que la versión recordada sigue vigente.
